# SPEC · 设备音量与系统音效

> 引入版本：v1.0.9 开发中（2026-11-15）。关联：`SPEC-transport-wired-bluetooth.md`。
> 2026-11-17 扩展：每应用音量、麦克风检测/控制/电平测试。

## 0. 音频控制台（2026-11-17）

### 0.1 目标

- 耳机/音频设备在应用内控制**系统输出**：默认端点音量、静音、打开系统设置。
- **每应用音量/静音**：枚举当前音频会话，按进程聚合，单独调整每个程序的音量。
- **麦克风**：识别耳机是否带麦克风（按同一物理容器/名称匹配），提供输入音量、
  静音与实时电平测试。
- **每应用输出/输入设备**：调用 Windows 内部 `AudioPolicyConfig`
  （`Windows.Media.Internal.AudioPolicyConfig`，Win10 1803+/Win11），
  按应用写入输出与输入端点。该接口未公开，vtable/ID 格式按公开社区实现固定；
  失败时回退到只读显示 + Windows 设置入口。部分应用需重新开始播放/录音后生效。

### 0.2 状态所有权

```text
Windows Core Audio（系统事实）
  ├─ 端点音量/静音        ← audio::SetVolume/SetMute（UI 点击写入）
  ├─ 会话音量/静音        ← audio::SetAppVolume/SetAppMute（UI 点击写入）
  ├─ 应用输出/输入设备    ← audio::SetAppEndpoint（AudioPolicyConfig，UI 下拉写入）
  └─ 采集端点电平         ← MicMonitor 线程（唯一写入 atomic level）
UI（MainWindow / AudioCenterWindow）
  ├─ 每次打开/刷新读取端点与会话快照，不把本地缓存当事实
  ├─ 音量拖动立即写入系统，并以写入值刷新本地显示
  └─ 麦克风电平由 33 ms 定时器读取 MicMonitor::Level()
```

- 系统音量键、托盘、其它程序修改后，本地显示在下次刷新（≤2 s）同步。
- 麦克风监听线程只存在一个；切换端点/停止测试时必须 Stop + Join，避免句柄泄漏。
- `MicMonitor::Start` 立即返回，WASAPI 初始化在后台线程完成。UI 侧给启动
  **1500 ms 宽限**：宽限期内 `running()==false` 且无错误时显示“正在启动”，
  不能复位按钮/杀掉 33 ms 定时器；超时或出现错误时调用 Stop + Join，
  保证不会留下“UI 已停止、后台仍在采集”的线程。
- 麦克风卡的“打开 Windows 声音设置”链接只在 `micIndex < 0`（未检测到麦克风）
  时参与命中测试；否则它的矩形会覆盖静音胶囊/输入音量行。
- 采集线程以 MTA 初始化 COM；UI 线程保持现有 STA。
- **拖动期间的会话缓存（2026-11-25，B03）**：`AudioCenterWindow` 在应用音量条按下时
  `AppVolumeWriter::Open(pid)` 解析一次该 PID 的活动会话，拖动期间直接写缓存接口；
  `WM_LBUTTONUP` / `WM_CAPTURECHANGED` / 面板关闭 / 拖动中止时 `Close()`。
  缓存只缩短写入路径，不是“系统事实”：显示值仍来自 2 s 刷新快照。

### 0.3 接口（`src/audio.h`）

- `Endpoint` 增加 `flow`、`containerId`、`isDefault`。
- `ListRenderEndpoints()` / `ListCaptureEndpoints()`：活动端点 + 音量/静音/容器 id。
- `MatchCaptureEndpoint(deviceName, product, renderContainerId, captures)`：
  1) 同一 `containerId` 优先；2) 端点名/去括号名包含设备名/产品名；
  3) ≥4 字符字母数字片段；无匹配返回 -1。
- `ListSessions()`：枚举活动渲染端点上的 `IAudioSessionManager2` 会话，按
  `(pid)` 聚合，返回名称、进程 id、会话数、音量、静音、端点名。
- `SetAppVolume(pid, percent)` / `SetAppMute(pid, mute)`：对该 pid 的所有会话写入。
  写入路径只枚举活动会话并 QI `ISimpleAudioVolume`，不读显示名/端点名/当前值。
- `AppVolumeWriter`（拖动专用，2026-11-25）：`Open(pid)` 按 PID 枚举一次活动会话并
  缓存 `ISimpleAudioVolume`（AddRef）；`SetVolume` / `SetMute` / `SetVolumeUnmuted`
  直接写缓存，返回成功写入的会话数；`Close()` 释放。一次拖动是 O(1) 次枚举，而不是
  每次 `WM_MOUSEMOVE` 枚举全部端点/会话（原实现每条消息还多做一遍静音写入枚举）。
- `PlanAppWrite(written, reopened)`（可单测）：写入 0 个会话时先 `Reopen` 一次
  （应用可能刚重建会话），仍失败则 `GiveUp`；不允许每条鼠标消息都重新枚举。
- `SetAppEndpoint(pid, capture, endpointId)` / `GetAppEndpoint(pid, capture, id)`：
  - 激活 `Windows.Media.Internal.AudioPolicyConfig`，QI 已知 IID
    （`AB3D4648-…` / `2A59116D-…` / `32AA8E18-…`；三者 vtable 槽位一致）。
  - 方法位于 **vtable 25/26**（IUnknown 0–2、IInspectable 3–5、19 个未使用方法 6–24）。
  - `deviceId` 必须是 `\\?\SWD#MMDEVAPI#<IMMDevice id>#{render|capture GUID}`；
    `endpointId` 为空表示恢复默认（传 null HSTRING）。
  - 对 `eConsole/eMultimedia/eCommunications` 三个角色写入；Get 依次读取并还原成
    IMMDevice id。`PROCESS_NO_AUDIO`（E_INVALIDARG）视为该应用当前无此方向会话。
- `MicMonitor`：`Start(captureEndpointId)`、`Stop()`、`Level()`（0..1 峰值）、
  `running()`、`error()`；共享模式 100 ms 缓冲，线程内计算峰值。
- `OpenSoundSettings()`：`ms-settings:sound`，失败退回 `mmsys.cpl`。

### 0.4 界面

- 设备页“音量与音效”卡保留设备音量/系统输出/静音/打开设置，并新增
  “音频控制台 ›”。
- 音频面板嵌入主窗口内容区（子窗口，不新建顶层窗口）：
  - 设备页“音量与音效”卡点击「音频控制台 ›」后，隐藏设备列表，内容区展开
    音频面板；内容头显示“音频控制”。面板左上「‹ 返回设备」或点击任意导航项折叠。
  - 面板为 `WS_CHILD` 子窗口，DPI/字体跟随主窗口，关闭主窗口到托盘时折叠并停止
    麦克风监听。
  - 左列：系统输出（默认端点名、音量、静音）、麦克风（匹配到的采集端点名、
    输入音量、静音、20 段电平条、“开始/停止测试”）。
  - 右列：应用音量列表（进程名 + 音量 + 静音），选中后显示大音量条、静音胶囊、
    会话数、**输出设备**与**输入设备**下拉框（“默认”/各端点）、当前实际播放端点；
    下拉写入按应用持久化，部分应用需重新开始播放/录音后生效。
  - 应用音量拖动在按下时锁定 PID 并使用 `AppVolumeWriter` 缓存该 PID 的会话接口；
    2 s 刷新重建列表后若该 PID 已消失，立即结束拖动、释放鼠标捕获并 `Close()` 缓存，
    不能把音量写到另一个应用。列表重建保留滚动位置。
    写入失败先按 `PlanAppWrite` 重开一次缓存，仍失败提示“会话可能已结束”并结束拖动。
  - 未检测到麦克风：显示“未检测到该设备的麦克风”，不显示电平条与测试按钮。
  - demo 模式：面板可展开，内容头提示“演示模式 · 麦克风测试使用真实设备”。

### 0.5 验收

1. 选中带麦克风的耳机 → 音频面板显示麦克风卡、输入音量可用。
2. 对着麦克风说话 → 电平条实时变化，停止后归零。
3. 播放音频的程序出现在应用列表；拖动其音量 → 系统音量混合器中该应用读数
   同步变化；静音胶囊 → 该应用静音。
4. 系统输出音量/静音与应用内读数一致（±1%）。
5. 未检测到麦克风的耳机 → 显示无麦克风提示，不出现电平条。
6. 折叠音频面板 → 麦克风监听停止；再次展开不会叠加线程/句柄。
7. 每应用输出设备：选中应用 → 输出设备改为另一端点 → `GetAppEndpoint` 返回该端点；
   重启该应用后，新会话落在目标端点；改回“默认”后 Get 为空。
8. 每应用输入设备：同上 flow=eCapture；至少验证 Set/Get 与清空。
9. 撤销/恢复：改回“默认”不残留持久化覆盖。
10. 应用音量拖动（B03）：按住拖动时系统音量混合器中该应用读数连续跟随；
    一次拖动只在按下时枚举一次会话（失败时最多再重开一次），不再每条
    `WM_MOUSEMOVE` 枚举；拖动中该应用会话结束 → 提示“会话可能已结束”且
    不写到其它应用。

### 0.6 边界

- 不做回声/监听播放（会啸叫），只做电平柱状图。
- 不写注册表、不装虚拟声卡、不 hook 其它进程。
- 每应用设备使用未公开的 AudioPolicyConfig，可能随 Windows 更新失效；只在
  已知 IID 上调用，激活/写入失败时回退到只读显示与系统设置入口，不崩溃。
- 已运行中的音频流未必即时迁移；部分应用需重新开始播放/录音。
- 麦克风被 Windows 隐私设置阻止时，电平条显示错误提示，不反复重试。
- 拖动缓存只覆盖按下那一刻的会话：拖动期间应用新开的第二个会话不在缓存内，
  下次拖动或 2 s 刷新后才会覆盖；这比每帧枚举的代价小得多，且拖动是短时操作。

## 1. 原有端点音量能力（v1.0.9）

### 1.1 目标

- 在设备页直接调整**该设备对应播放端点**的音量/静音（耳机优先）。
- “系统输出”行可指定**任一活动播放端点**；默认跟随 Windows 系统默认输出。
- 提供进入 Windows「声音」设置（声音方案、空间音效、增强等）的入口。

## 2. 能力边界

本轮只做 Core Audio（WASAPI）的**端点级**控制：

| 能做 | 不做 |
| --- | --- |
| 枚举活动播放端点、读音量/静音 | 切换系统默认播放设备 |
| 设置指定端点音量（0–100）与静音 | 每应用音量混合器（IAudioSession*） |
| 打开 `ms-settings:sound` | 直接改写声音方案/注册表、空间音效开关 |
| `--diag` 输出端点摘要 | 后台实时监听外部音量变化 |

> “系统音效设置”在本轮解释为：**默认输出音量/静音 + 一键打开 Windows 声音设置**
> （声音方案、通知音效、空间音效都在那里）。应用内不改写系统声音方案。

## 3. 实现

- `src/audio.h/.cpp`（Core Audio，`-lole32 -luuid`）：
  - `ListRenderEndpoints()`：`IMMDeviceEnumerator::EnumAudioEndpoints(eRender,
    DEVICE_STATE_ACTIVE)`，读 `PKEY_Device_FriendlyName`，`Activate(IID_IAudioEndpointVolume)`
    后取 `GetMasterVolumeLevelScalar` / `GetMute`；默认端点由
    `GetDefaultAudioEndpoint(eRender, eConsole)` 比对 id。
  - `SetVolume` / `SetMute` / `GetVolume`：按端点 id 打开设备并写入。
  - `MatchEndpoint(deviceName, product, endpoints)`（纯逻辑，可单测）：
    1. 端点名（含去括号版本）包含完整设备名/产品名 → 高分，取最长匹配；
    2. 否则比较 ≥4 字符的字母数字片段（G733 / Arctis…）；
    3. 同分优先系统默认端点；无匹配返回 -1。
  - `OpenSoundSettings()`：`ms-settings:sound`，失败退回 `control.exe mmsys.cpl,,0`。
- UI（`src/ui.cpp`）：
  - 耳机、或名称匹配到端点的设备，在“设备信息”的格子显示**音量与音效**卡；
    其它设备仍是设备信息卡。
  - 卡片内容：设备音量（百分比输入 + 音量条 + 静音胶囊）、系统输出（同上）、
    端点名、匹配状态说明、“打开 Windows 声音设置 ›”链接。
  - 交互：按下音量条即跳转并进入拖动（`volDrag_` + `SetCapture`），
    拖动时自动取消静音（与系统音量条一致）；点击静音胶囊切换；
    点击链接打开系统设置。`WM_CAPTURECHANGED` 会清掉拖动状态。
  - **数字输入（2026-11-21，P0）**：两个百分比位置各有一个原生 `EDIT`
    （`ID_VOL_DEV` / `ID_VOL_SYS`，`ES_NUMBER`）。输入 0–100 直接写入对应端点；
    `EN_CHANGE` 实时生效，`EN_KILLFOCUS` 与 `Enter` 归一化显示。
    `audio::ParseVolumePercent` 只接受纯数字（首尾空格容忍），越界夹到 0/100，
    空串/非数字保留当前值；范围由函数与 EDIT 双重约束，不能写出 0–100 之外的值。
  - 两个输入框/两个音量条各自绑定 `audioDevId_` 与 `audioSysId_`：两个端点不同时
    独立写入；本机设备端点就是系统默认端点时，按 Windows 语义同步显示同一数值。
  - **系统输出端点选择（2026-11-21）**：音量卡新增原生下拉 `ID_SYS_ENDPOINT`
    （`CBS_DROPDOWNLIST`）。第一项为 `跟随系统默认 · <默认端点名>`，其余为当前
    活动播放端点。
    - 选中具体端点后 `audioSysId_` 固定为该端点，只影响“系统输出”行与其静音；
      “设备音量”仍绑定匹配到的设备端点。
    - 选“跟随系统默认”或默认端点本身时清空固定，继续跟随 Windows 默认输出。
    - 两行指向同一端点时仍按 Windows 语义同值；选择不同端点后才真正独立。
    - 固定端点在刷新中消失时自动回退到“跟随系统默认”。
    - 选择仅本次运行有效（会话级），不写配置；重启后回到跟随默认。
    - 下拉加入键盘 Tab 链（两个音量 EDIT 之后、DPI 之前）。
  - 音量 `EDIT` 加入键盘 Tab 链（刷新按钮之后、DPI 之前），可用键盘直接输入。
  - 数值在 `UpdateControlsFromDevice()` 时重读（设备切换、5 s 扫描），
    不做后台轮询；写入后本地立即更新并发起一次重绘。正在输入的框不会被
    5 s 刷新覆盖，失焦后再归一化。

## 4. 验收

- 选中耳机：右下卡显示“音量与音效”，左右两个音量条与静音胶囊可用。
- 拖动“设备音量”到 75%：系统对应端点读数变为 ~75%（实测 43% → 76% → 恢复 43%）。
- 数字输入 `37` + Enter：设备音量与系统输出（同一端点时）都变为 37%，条同步。
- 数字输入 `150` + Enter：夹到 100%；输入空串/字母不改变当前值；重启/切设备后
  显示仍与系统端点一致。
- 两个端点不同（设备端点非默认输出）时，两个输入框/音量条独立写入，不互相覆盖。
- 系统输出端点下拉（2026-11-21）：
  - Buds 为默认输出时，在“系统输出端点”选择“扬声器 (Realtek)”：系统输出行显示
    扬声器音量，拖动/输入只改扬声器；“设备音量”仍改 Buds，两行数值独立。
  - 选回“跟随系统默认”：系统输出行回到默认端点；Windows 默认变化后自动跟随。
  - 固定端点被拔出/停用后，下一次刷新回到“跟随系统默认”。
  - 重启应用后下拉回到“跟随系统默认”（会话级，不持久化）。
- 点击静音胶囊：端点 mute=1；再点恢复 mute=0。
- 点击“打开 Windows 声音设置”：打开系统声音设置页（`ms-settings:sound`）。
- 未匹配到端点（如 demo 的 G733 在本机没有对应端点）：卡上明确写出
  “未匹配到该设备的音频端点，当前控制系统默认输出”，两个音量条控制默认端点。
- `--diag` 输出 `音频: N 个播放端点 · 默认「名称」xx%`。

## 5. 已知限制

- 端点名与设备名差异过大时匹配不到（例如端点只写“扬声器”，设备名是型号）；
  此时回退到系统默认输出并显示提示，不做模糊猜测。
- “设备音量”和“系统输出”本质上是两个播放端点；同一端点只有一个音量值，
  不可能显示两个不同数字。Buds4 Pro 的硬件音量（AVRCP absolute volume）就是
  该端点音量，Samsung SPP 没有独立的 A2DP 音量通道。
- 系统输出端点选择为会话级，不持久化；重启应用后回到“跟随系统默认”。
- 外部（音量键、系统托盘）修改音量后，本应用要等下一次设备刷新才同步。
- 纯 USB Audio 类耳机没有 HID 条目，仍不会出现在设备列表（见
  `SPEC-transport-wired-bluetooth.md` §1.1），因此也用不到这张卡。
- 蓝牙音频耳机（无 HID）自 2026-11-18 起会以只读条目出现在设备列表，
  可正常使用这张音量卡；其电量在 Windows 未暴露时不显示。

## 6. 耳机听力保护：推荐音量 ≤ 60%（2026-11-21）

### 6.1 目标与范围

- 对 `Kind::Headset` 且已匹配到播放端点的设备生效；卡上始终显示
  “听力保护：建议耳机音量不超过 60%”。
- “设备音量”行：只要控制的是该耳机端点，就受保护。
- “系统输出”行：只有其目标端点就是该耳机端点时受保护；固定到扬声器等
  其它端点时不受影响。
- 非耳机设备、未匹配到端点而回退系统默认时不显示该提示与同意框。

### 6.2 规则

- 推荐上限常量 `audio::kRecommendedHeadsetVolume = 60`。
- 未勾选同意时：
  - 当前 ≤60：请求 >60 时夹到 60 并写入 60，同时显示警告与同意复选框；
  - 当前 >60（例如外部设置）：不主动降低；请求继续升高时保持当前值
    （不允许继续升高），请求 ≤当前 时允许（可以降低）。
- 勾选“我已了解风险，允许超过 60%”：
  - 立即应用被拦截的待定值（如果存在）；之后允许 >60；
  - 同意状态在切换设备或重启应用后重置，不持久化。
- 取消勾选：不主动降低当前音量；之后的升高重新受 60 限制。
- 数字输入与拖动使用同一规则；被夹取后输入框立即归一化为实际值。

### 6.3 接口

- `audio::LimitHeadsetVolume(current, requested, allowAbove)` 纯函数（可单测）。
- UI 状态：`headsetLoudOk_`（已同意）、`headsetLoudWarn_`（显示警告/复选框）、
  `headsetLoudPending_`（待应用的超限值）；原生复选框 `ID_LOUD_OK`。

### 6.4 验收

1. Buds 当前 57，拖动设备音量到 80 → 停在 60，显示警告与同意框；端点读回 60。
2. 勾选同意 → 自动升到 80；再拖到 90 允许。
3. 取消勾选后从 80 拖到 90 → 保持 80；从 80 拖到 50 → 允许。
4. 系统输出固定到 Realtek 时，系统行不受 60 限制；只有设备行受保护。
5. 切换设备后同意状态重置；重新调高到 >60 需再次勾选。
6. 非耳机设备不显示听力保护提示与同意框。
