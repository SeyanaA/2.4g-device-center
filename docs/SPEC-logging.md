# 设备事件日志规格

> 状态：实现中 · 适用 v1.0.7+
>
> 目标：把“设备什么时候接上、什么时候掉线、电量怎么变”写成可回溯的日志，
> 排查电量异常时不用再靠截图和猜测。

## 1. 所有者与写入路径

- 唯一写入方：`DeviceManager::ScanOnce()`（后台扫描线程，默认 5s 一次）。
- 事件来源：合并前快照（`old`）与合并后快照（`now`）的差异。
- UI 线程、托盘、`--once` 都不写事件日志，避免多条写入路径。
- 写入失败不影响扫描、不影响 UI；不重试、不抛异常。

## 2. 文件与格式

目录：`%APPDATA%\2.4GCenter\events\`

文件名：`events-YYYY-MM-DD.log`（本地日期，UTF-8 无 BOM，CRLF）

每行一条：

```text
YYYY-MM-DD HH:MM:SS  TYPE  <identity>  <设备名>  <明细>
```

`identity` 为空时用 `id`；同一物理设备跨传输只记一条身份。

## 3. 事件类型

| TYPE | 触发条件 | 明细示例 |
| --- | --- | --- |
| `CONNECT` | 该 identity 本轮出现、上轮不存在 | `2.4G 无线 · 95% · 电池供电` |
| `DISCONNECT` | 上轮存在、本轮不在快照（离线被过滤也计入） | `最后读数 94%` |
| `BATTERY` | 同一 identity 电量或电压变化，或首次拿到读数 | `95% -> 94% · 4076 mV -> 4050 mV` |
| `CHARGE` | 充电位翻转 | `电池供电 -> 充电中` |

规则：

- 同一 identity 连续两轮读数完全相同时**不写**，避免 5s 轮询刷屏。
- 首次扫描把所有在线设备记为 `CONNECT`，方便确认启动时刻。
- demo 模式不写。
- 不记录帧原始字节、不记录路径、不记录任何凭据。

## 4. 保留策略

- 保留**当天 + 前 6 天**，共 7 个文件；更早的 `events-*.log` 自动删除。
- 清理时机：进程启动时一次，之后每天首次写入时一次；同一天不重复扫描目录。
- 只删除本目录下匹配 `events-YYYY-MM-DD.log` 且日期早于窗口的文件；
  不匹配的文件、其他目录一律不碰。
- 日期按本地时间计算，跨月/跨年由日期序号比较，字符串比较不参与。

## 5. 查看入口

- 托盘菜单新增「设备事件日志」：`ShellExecuteW("open", EventLogPath())`，
  默认编辑器打开今天的文件。
- 已有「打开日志」保留，指向 `log.txt`（应用诊断日志）。

## 6. 验收场景

1. 启动应用 → 今天的 `events-*.log` 出现，含每个在线设备的 `CONNECT`。
2. 设备休眠掉线 → `DISCONNECT` 一条；唤醒 → 新 `CONNECT` 一条。
3. 电量 95%→94% → 一条 `BATTERY`；下一轮仍 94% → 不重复。
4. 插线开始充电 → 一条 `CHARGE`。
5. `events\` 下预置 `events-2020-01-01.log` → 启动后被删除。
6. 恰好 7 天前的文件保留，8 天前的文件删除。
7. 删除/改名日志目录导致写入失败 → 扫描与 UI 正常。
